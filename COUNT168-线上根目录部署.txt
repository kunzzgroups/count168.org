================================================================================
  让 https://count168.org/ 打开 React 登录（不是只在本机 localhost:5173）
================================================================================

【原理】
  线上是 Apache + PHP。根目录要同时有：
  · index.html          ← Vite 打的 React 入口（首屏用）
  · index.php           ← 旧站入口可保留
  · assets/  images/   ← 前端资源
  · api/  *.php         ← 接口不变
  根 .htaccess 里已写：先找 index.html，再 index.php；没有真实文件时回退到 index.html（SPA）

【你只要记住这两条命令】
  第一次装依赖（只做一次）：

    cd client
    npm install

  以后每次要把 React 同步到**网站根**（和 index.php 同一层）：

    cd client
    npm run build:site

  或站在**仓库最外层** count168.org 里一条命令（等价）：

    npm run build:web

  （`build:web` 会进 client 里执行 `build:site`；没装过 client 依赖时会报错，请先 `cd client` 再 `npm install`。）

  成功后在**本机仓库根目录**会多出/覆盖这些（与线上一致）：

    index.html          ← React
    assets/             ← JS/CSS 哈希名
    images/             ← count_bg、telegram 等（与 public 里合并）

【上传到主机】
  用 FTP / 面板文件管理 / git，把**整个网站根**同步到主机的 public_html（或你域名指向的目录）：
  · 必须包含新出现的 index.html、assets/、images/ 中更新项
  · 必须包含已更新的 .htaccess
  **不要**只上传 client 子文件夹，那是错的。

【验证】
  浏览器打开 https://count168.org/ 应看到 React 页（不是 view-source 里纯 PHP 那份）。
  接口仍是同域，例如 /login_process.php、/api/...

【如果打开还是旧版】
  · 清浏览器缓存，强刷 Ctrl+F5
  · 确认服务器上**真的出现**了根目录的 index.html（可 FTP 看）
  · 问主机商：是否 Apache、是否允许 .htaccess 的 DirectoryIndex 与 mod_rewrite
  · Nginx 主机不能用本仓库 .htaccess，需自己配 try_files 与 index 顺序
