Count168 前端（React /app）+ 后端（PHP /api/v1/）

【必传目录与文件】
1) 整个 /app/ 目录：含 index.html、assets/ 下 .js .css、.htaccess（npm run build 后自动从 frontend/deployment 恢复）、favicon 等（在本地先执行: cd frontend && npm run build）
2) 整个 /api/v1/（你的 PHP 接口）
3) 本根目录的 .htaccess
4) /includes/spa_redirect.php（旧 .php 入口 301 到 SPA 会用到）
5) 已替换为“跳转”的旧入口 .php：index.php、dashboard.php 等（与仓库根目录同名文件一致时可直接覆盖）

【访问方式（生产默认 Hash 路由，共享主机最省事）】
- 在浏览器打开: https://你的域名/app/index.html
- 或先打开: https://你的域名/index.php  → 会 301 到 /app/index.html#（含 #/login 等，见 includes/spa_redirect.php）
- 正常登录后，地址里会出现 #/dashboard、#/modules/...  这是预期现象

【API】
- 与站点同域时，前端已写死 baseURL: /api/v1

【若坚持不要 # 的 URL（History 模式）】
- frontend 下 build: 设置 VITE_SPA_USE_BROWSER=1
- 将 includes/spa_redirect.php 内 C168_SPA_USE_HASH 改为 false
- 并确保本 .htaccess 中「回退到 /app/index.html」规则在主机上生效，否则 /app/login 会 404

【若 /app/index.html 仍 404】
- 在文件管理器确认: (网站根)/app/index.html 的确存在
- 确认域名所绑定的「网站根」就是当前这个 public_html（或 cPanel 里显示 Document root 的那一层）
